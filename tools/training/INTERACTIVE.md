# Live policy simulation

In **Inspect**, select a run/checkpoint and choose **Start selected policy**. Sessions open paused. **Velocity** sets body-frame forward/lateral velocity in m/s and yaw rate in rad/s. **Push** applies a world-frame horizontal force in newtons for the requested simulation duration, rounded up to a control step. Resume, pause, single-step and deterministic restart control actual physics. The timeline buttons use these same controls during a live session.

The implemented adapters are the captured generic MuJoCo task, the specialized Open Duck task, Microduck's official mjlab/BAM task, and native Zealot G1. Both legacy and authored duck checkpoints work. G1 captures the official flat MuJoCo model and controller, including history, two-step action lag, 12 learned leg targets and 17 held waist/arm joints. Named telemetry includes all 29 joints. CPU cart-pole is excluded from the current product scope at the user's request; existing reference artifacts remain readable.

Simulation uses CPU physics and normalized ONNX inference. Existing MPS/CUDA training settings are unchanged. The scene is the captured task's flat floor. Restart uses seed 42 and the current velocity command; it clears active forces and starts a new recorded episode. A fall or the task's episode time limit pauses simulation. Resume cannot continue a terminal episode; restart is required.

Each session captures a parity-checked policy export, source checkpoint, available model/task snapshots and run recipe under `simulations/sim<timestamp>/`. Source/model/robot checks must pass before readiness. The GUI accepts named poses only for that robot and checkpoint. Changing the selected run, checkpoint, robot or workspace closes the old physics session. Closing or crashing the GUI closes the worker's stdin pipe; the worker flushes and stops. A bounded process reaper handles a hung worker on normal GUI teardown.

`simulation-motion.jsonl` records every control transition independently of viewport updates: original-precision pose, policy input, next observation, action, physical targets/torques, body command, world force, episode boundary, control acknowledgement, seed and policy/checkpoint digests. Simulation time counts recorded physics steps and excludes wall time spent paused. Recording is bounded to 100,000 frames / 256 MiB. Sessions do not automatically reset after falling, so saved terminal poses remain inspectable.

**Save and review** pauses at an acknowledged step, saves a review document and opens it. An I/O failure retains the paused session for retry. **Recover…** imports a retained session folder after leaving the workspace or restarting Studio. Review offers Command and World force channels; edited exports retain telemetry and provenance. A changed robot, checkpoint digest, session identity or policy digest is rejected when recovering a source.

Worker protocol: one JSON object per stdin line with an increasing integer `id` and `op`. Operations are `command` (`value: [vx,vy,yaw]`), `push` (`force: [x,y,z]`, `seconds`), `pause`, `resume`, `step`, `restart` and `stop`. `status.json` is atomically published with the last acknowledged id, physical sequence, state, error and latest named pose. A command acknowledgement does not imply command-tracking success: short acceptance checkpoints often fall or fail to track velocities.

The Microduck integration also fixes an observation-cache issue: changing a command after `reset/step` must invalidate cached observations without advancing history. Captured Microduck held-out evaluation uses the same correction.
